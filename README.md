# OriginCheck

[![CI](https://github.com/enginoor/idea/actions/workflows/ci.yml/badge.svg)](https://github.com/enginoor/idea/actions/workflows/ci.yml)

A native macOS app that answers one question: was this text or file generated by an AI model?

It uses two signals:

- **Text detection for any model family.** The text side is a local statistical detector that fuses five signals: sentence-length burstiness, phrase repetition, vocabulary surprisal (perplexity), rare-word rate, and a database of AI phrasing patterns tagged by model family (ChatGPT-style, Claude-style, Gemini-style, and generic). It reports AI-typical patterns with a confidence ceiling of moderate, plus soft style hints. The frequency dictionary and phrase database ship inside the app, so detection works fully offline with nothing installed. It is explicitly labeled a heuristic, never an official watermark detector, which has not been released for any model.
- **C2PA metadata verification.** Claude and other tools attach signed C2PA provenance metadata to generated files such as png, jpg, and svg. This side is cryptographically verifiable and is the strongest signal in the product. PNG files are verified by a built-in reader with no installed tools; other formats use the reference `c2patool` when available.

The product philosophy is honesty. A detected pattern means the content shows AI-generation characteristics; it is not proof of AI authorship. No signal does not prove human authorship. Every verdict carries a caveat, an evidence list, and style hints when the phrasing database found enough matches.

## The engine

`OriginCheckEngine` is a dependency-free Swift library. It owns:

- The data model (`VerdictKind`, `Confidence`, `TextVerdict`, `FileVerdict`, `C2PAClaim`, `HistoryRecord`).
- `C2PAVerifier`, which runs `c2patool` and parses its JSON output into a `FileVerdict`.
- `MediaFormat`, the list of formats c2patool verifies today, with case-insensitive extension parsing.
- `FolderVerifier`, which scans a folder, verifies every supported file, and returns a `BatchReport` with counts, per-file verdicts, and failures.
- `TextWatermarkAnalyzer`, with a provider protocol, a local statistical analyzer (burstiness + repetition heuristics, with raw statistics shown as evidence), and a scaffolded `AnthropicDetectionAPIProvider` behind a feature flag.
- `VerdictCombiner`, which merges provider results and applies the confidence rules.
- `JSONHistoryStore`, hash-only by default, raw content only with explicit consent.
- A dependency-free SHA-256 implementation for input hashing.

Confidence rules: unknowns reduce confidence, never increase it. A valid signature with a known signer is the strongest evidence. An unknown signer caps confidence. Short text can never reach high confidence.

## Building and testing

The engine is tested on Linux and macOS:

```
swift test
```

The app target requires macOS 14 or later and Xcode:

```
cd App
swift run OriginCheck
```

or open `App/Package.swift` in Xcode. SwiftPM identifies the engine by the checkout folder name, so build the app from a checkout of this repo whose folder is named `idea`. If you cloned into a differently named folder, change the `package:` reference in `App/Package.swift` to match.

## CI and releases

GitHub Actions runs on every push and pull request:

- `ci.yml` runs the engine test suite on Linux (Swift 6.0.3) and macOS, and builds the macOS app on a macOS runner. A red check means something broke; the app target gets its first real compile here, since the development sandbox is Linux.
- `release.yml` is the single publisher. It gates on the engine tests, builds the app in release mode, packages `OriginCheck.app` with the embedded Sparkle framework, creates and validates a branded drag-to-install DMG, signs the DMG with Sparkle's EdDSA key, updates the update feed, and publishes a GitHub release carrying the DMG and a verified `checksums.txt`. It runs on `v*` tag pushes and manually from the Actions tab.

Cut a release with one command:

```
bash Scripts/release.sh v1.2.0
```

The script validates the repository, verifies CI is green for the commit, optionally pre-flights the build and DMG on a Mac, creates the tag, pushes it, waits for the Release workflow, and verifies the published DMG. Pushing a tag directly works too:

```
git tag v1.2.0
git push origin v1.2.0
```

The app checks the update feed (`appcast.xml`) through Sparkle and offers verified automatic updates. Full operations documentation, key setup, and update-testing instructions live in [RELEASING.md](RELEASING.md). Notarization is not wired up yet and will need an Apple Developer certificate.

## File verification: built-in PNG reader and c2patool

PNG files are verified out of the box by a pure-Swift reader (`PNGC2PAReader`) that walks the file's `iTXt` chunks, decodes the Base64 JUMBF superbox, and extracts the C2PA manifest store. No tool is needed, which matters because PNG is the most common format for AI-generated images. The built-in reader proves that a provenance manifest exists and who claims to have created the file, but it cannot validate the signature: that needs the reference tool, and the verdict says so honestly.

For full signature validation and for every other format, file verification shells out to `c2patool`, the reference command line tool from the Content Authenticity Initiative:

```
cargo install c2patool
```

or with Homebrew if a formula is available. The tool path is injectable (`C2PAVerifier(toolPath:)`); when the tool is reachable it is always preferred over the bundled reader. The engine throws a clear error if the tool is missing and the file is not a PNG. The macOS app exposes the path in Settings, so a Homebrew install location or a custom build can be pointed at without rebuilding.

Supported formats follow c2patool: png, jpg, jpeg, svg, webp, avif, heic, heif, tif, tiff, dng, mp4, mov, m4a, mp3, wav, and pdf (read-only). The macOS app's file picker and drop zone accept the full list, derived from the engine's format table so the UI can never drift from what verification supports. Folder scans accept everything too.

## Batch folder verification

`FolderVerifier` scans a folder recursively and verifies every supported file it finds:

```swift
let verifier = FolderVerifier() // c2paToolPath is injectable
let report = try await verifier.verifyDirectory(at: folderURL)
print(report.summary.watermarked, report.summary.noManifest, report.summary.failed)
```

The report card holds factual counts, one verdict per file, and a list of failures. One broken file never stops the scan. Hidden files and unsupported extensions are skipped, and `toolMissing` reports honestly when c2patool cannot be launched. Each scan is written to history as a summary record (kind `.batchScan`): the counts and the scanned location, never the per-file list or any file contents. A folder has no single verdict kind, so the record reports counts, not a confidence percentage.

To try the engine against realistic manifests without installing c2patool, point it at the mock tool:

```
swift run --package-path App OriginCheck   # or in your own harness:
C2PAVerifier(toolPath: "Fixtures/mock-tools/c2patool")
```

The mock picks a payload by input file name: names containing `intact`, `modified`, `unknown`, or `expired` produce the matching fixture, anything else reports no manifest.

## Test fixtures

`Fixtures/c2pa/` holds reference manifest payloads in the shape c2patool prints:

- `signed-intact.json`: Claude-signed, valid signature, unmodified.
- `signed-modified.json`: Claude-signed, valid signature, asset changed after signing.
- `unknown-signer.json`: signed by an unknown entity.
- `expired-cert.json`: expired signing certificate.
- `expired-hash-mismatch.json`: expired certificate plus a hash mismatch, which must not be reported as a modification because the signature does not verify.

Every fixture has an expected verdict asserted in the test suite, so a regression anywhere in the parsing or confidence logic is caught.

## The text detection integration

The local detector (`LocalStatisticalAnalyzer`) scores text for AI-typical statistical patterns across any model family. It fuses five signals:

- **Burstiness**: the coefficient of variation of sentence lengths. AI prose is rhythmically uniform; human writing is bursty.
- **Phrase repetition**: how often adjacent word pairs repeat.
- **Perplexity**: how surprising the vocabulary choices are, measured against a bundled English frequency dictionary. AI prose stays in the common middle of the vocabulary.
- **Rare-word rate**: the same vocabulary signal expressed as a rate.
- **AI phrasing**: a bundled database of phrases that appear disproportionately often in AI-generated prose, tagged by model family. Match density feeds the score and produces the verdict's soft style hints (for example "ChatGPT-style").

The five signals combine into an AI-typical score (0...1) that maps to a verdict (AI-typical pattern detected, no AI-typical pattern, or inconclusive) with a confidence ceiling of moderate: without any model's released detection parameters, a high-confidence claim would be dishonest. Every verdict carries the raw statistics as evidence, the matched phrases, the style hints, and a caveat explaining that the heuristic is a signal, not proof.

The detection data ships in `Sources/OriginCheckEngine/Resources/`: `english-frequencies.tsv` (the frequency dictionary), `ai-phrases.json` (the phrase database), and `sample-passages.json` (bundled samples for the app's Sample button). The packaging script embeds the generated resource bundle into OriginCheck.app, and the release validator refuses to ship a build without it. This is what makes the app fully standalone: no downloads, no network, no installed tools for text detection.

When Anthropic releases its detection API, implement the real call inside `AnthropicDetectionAPIProvider`, keep the provider interface unchanged, and flip the feature flag. The user's API key is read from the Keychain. The official detector will replace the heuristic for providers that support it.

## Not built here, on purpose

- No watermark removal or circumvention.
- No statistical AI-ness scoring presented as proof of authorship: the local heuristic is labeled as a heuristic signal with a confidence ceiling, never as the watermark detector.
- No claim that a mark proves plagiarism or dishonesty.
- No cloud processing. Everything is local; the only optional network feature is the Anthropic API provider with the user's own key.
