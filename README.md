# OriginCheck

A native macOS app that answers one question: was this text or file generated by Claude?

It uses two signals:

- **Text watermark analysis.** Claude models launched on or after August 2, 2026 embed an invisible watermark in generated prose. Anthropic has announced a detection API but has not released it. The text side is built as a pluggable provider interface and reports the honest unavailable state until that API ships.
- **C2PA metadata verification.** Claude attaches signed C2PA provenance metadata to generated files such as png, jpg, and svg. This side works today, is cryptographically verifiable, and is the core of the product.

The product philosophy is honesty. A detected mark means Claude likely processed the content; it is not proof of AI authorship. No mark does not prove human authorship. Every verdict carries a caveat and an evidence list.

## The engine

`OriginCheckEngine` is a dependency-free Swift library. It owns:

- The data model (`VerdictKind`, `Confidence`, `TextVerdict`, `FileVerdict`, `C2PAClaim`, `HistoryRecord`).
- `C2PAVerifier`, which runs `c2patool` and parses its JSON output into a `FileVerdict`.
- `TextWatermarkAnalyzer`, with a provider protocol, a local analyzer that honestly reports that detection parameters are not published, and a scaffolded `AnthropicDetectionAPIProvider` behind a feature flag.
- `VerdictCombiner`, which merges provider results and applies the confidence rules.
- `JSONHistoryStore`, hash-only by default, raw content only with explicit consent.
- A dependency-free SHA-256 implementation for input hashing.

Confidence rules: unknowns reduce confidence, never increase it. A valid signature with a known signer is the strongest evidence. An unknown signer caps confidence. Short text can never reach high confidence.

## Building and testing

The engine is tested on Linux and macOS:

```
swift test
```

The app target requires macOS 14 or later and Xcode:

```
cd App
swift run OriginCheck
```

or open `App/Package.swift` in Xcode.

## c2patool

File verification shells out to `c2patool`, the reference command line tool from the Content Authenticity Initiative. Install it once:

```
cargo install c2patool
```

or with Homebrew if a formula is available. The tool path is injectable (`C2PAVerifier(toolPath:)`), and the engine throws a clear error if the tool is missing.

To try the engine against realistic manifests without installing c2patool, point it at the mock tool:

```
swift run --package-path App OriginCheck   # or in your own harness:
C2PAVerifier(toolPath: "Fixtures/mock-tools/c2patool")
```

The mock picks a payload by input file name: names containing `intact`, `modified`, `unknown`, or `expired` produce the matching fixture, anything else reports no manifest.

## Test fixtures

`Fixtures/c2pa/` holds reference manifest payloads in the shape c2patool prints:

- `signed-intact.json`: Claude-signed, valid signature, unmodified.
- `signed-modified.json`: Claude-signed, valid signature, asset changed after signing.
- `unknown-signer.json`: signed by an unknown entity.
- `expired-cert.json`: expired signing certificate.

Every fixture has an expected verdict asserted in the test suite, so a regression anywhere in the parsing or confidence logic is caught.

## The text detection integration

When Anthropic releases its detection API, implement the real call inside `AnthropicDetectionAPIProvider`, keep the provider interface unchanged, and flip the feature flag. The user's API key is read from the Keychain. Until then the provider reports the honest unavailable state; nothing is guessed, and no network call is made.

## Not built here, on purpose

- No watermark removal or circumvention.
- No statistical AI-ness scoring presented as proof.
- No claim that a mark proves plagiarism or dishonesty.
- No cloud processing. Everything is local; the only optional network feature is the Anthropic API provider with the user's own key.
