# agent.md

This file is the working memory for this product. It exists so that any future session starts from the thinking that shaped this app instead of rediscovering it. Read it before you change code. If a change fights something written here, update this file first and say why in your response.

## What this product is

Name: OriginCheck. A native macOS app that answers one question: was this text or file generated by an AI model? (2026-08-17: multi-model, not Claude-specific anymore.)

It works through two technically opposite signals:

1. Text detection for any model family. The local detector fuses five signals: sentence-length burstiness (coefficient of variation), repeated-bigram rate, vocabulary surprisal (perplexity against a bundled English frequency dictionary), rare-word rate, and AI phrasing density (a bundled database of phrases tagged by model family). It reports "AI-typical pattern detected" / "no AI-typical pattern" / "inconclusive" with a confidence ceiling of moderate, soft style hints (ChatGPT-style, Claude-style, Gemini-style) when enough family-tagged phrases match, and the raw statistics shown as evidence. No model has released a watermark detector, so it is explicitly labeled a heuristic, never the watermark detector itself. The frequency dictionary, phrase database, and sample passages ship inside the app bundle, so text detection works fully offline with nothing installed.
2. C2PA metadata verification. Claude and other tools attach signed provenance metadata to generated files such as png, jpg, and svg. This side works today, is cryptographically verifiable, and is the product's core credibility. PNG files are verified by a built-in pure-Swift reader with no installed tools; other formats use the reference c2patool.

The repo is enginoor/idea. The owner's spec is complete and detailed; this file distills the thinking behind it so future sessions do not need to reread the whole document.

## The core asymmetry

A positive signal exists; a negative signal does not. A valid Claude-signed manifest is strong evidence the file was processed by Claude. The absence of a manifest proves nothing, because any re-save, conversion, screenshot, or upload pipeline can strip it. The same is true for the watermark: no mark can mean edited, paraphrased, translated, short, or generated by an older model.

The whole product follows from that: every verdict carries a caveat, every verdict carries evidence, and no negative result is ever presented as proof of human authorship.

## Product principles

1. Be the honest detector. Confidence is a range, not a verdict. Every screen educates, never accuses.
2. Positives are claims, not judgments. A detected mark means Claude likely processed the content. It does not prove AI authorship, plagiarism, or dishonesty.
3. Unknowns reduce confidence, never increase it. Unknown signer, expired certificate, missing metadata, short text: each pushes toward inconclusive.
4. The engine is the product. It is a pure Swift library with no UI imports, unit tested in CI, and treated like a library even inside the app.
5. Local and private by default. No telemetry, no accounts, no cloud. Raw content is stored only with explicit per-record consent; by default only a SHA-256 hash is kept.
6. No circumvention. No watermark removal, no detection-dodging advice. Ever.
7. Use the reference tooling. C2PA verification is done by c2patool, not reimplemented. The product's value is the UX and honest framing around verification, not the verification itself.
8. No overclaiming in marketing. The file side is real today; the text side is advertised as coming.

## Voice and punctuation rules, hard rules

- No em dashes anywhere: UI copy, code comments, this file, chat replies. Use commas, periods, colons, or a new sentence.
- No emojis anywhere in the product.
- No decorative icons. An icon may earn a place only if a word would be worse.
- Banned words and phrases: unleash, supercharge, seamless, elevate, empower, journey, unlock, dive into, game changer, level up, AI-powered, state of the art, robust, cutting-edge, revolutionize, effortless, magic.
- Write short sentences. Prefer concrete nouns. Say a verdict, not a decision framework.
- The caveat strings live in `Caveats.swift` and are part of the product contract. Never weaken them.

## Architecture

The engine (`Sources/OriginCheckEngine`) has no SwiftUI imports. Layers depend downward only:

- Models: `VerdictKind`, `Confidence`, `EvidenceItem`, `TextVerdict`, `FileVerdict`, `C2PAClaim`, `HistoryRecord`, `AnalysisOptions`, `ThresholdPreset`.
- `C2PAVerifier`: runs `c2patool` (path injectable), parses the manifest JSON leniently, maps to a `FileVerdict`. Unparseable output is reported as no manifest, never as a verdict on authorship. When the tool is not reachable, PNG files are routed to `PNGC2PAReader` (pure Swift: iTXt "c2pa" chunk, Base64 JUMBF walk, manifest store JSON), which reports manifest presence, generator, and claims but cannot validate the signature; the verdict says so. The tool always wins when it is reachable.
- `PNGC2PAReader`: self-contained PNG C2PA extraction. Walks PNG chunks, parses the iTXt "c2pa" text, Base64-decodes it, and recursively scans JUMBF boxes for the manifest store JSON. Tolerant: anything unparseable yields nil and the verifier reports no manifest, never a fabricated verdict.
- `FrequencyDictionary`: bundled `english-frequencies.tsv` (word + log10 frequency per million, coarse buckets). Provides surprisal stats (OOV and rare-word rates, average surprisal, perplexity term) with light inflection handling (ies/es/ed/ing/ly/s suffixes, double-consonant reduction, all-digit tokens treated as mid-frequency).
- `AIPhraseDatabase`: bundled `ai-phrases.json` (phrase, families, weight). Density of matches feeds the score; `familyHints(from:)` builds soft style attributions only when a family's matched weight clears the bar (1.0 default). Generic-family phrases never produce hints.
- `ModelFamily`: claude, chatgpt, gemini, generic; `ModelFamilyHint` carries the family, matched weight, and example phrases for the UI chips.
- `BundledResources`: lock-protected lazy loader for all three resource files via `Bundle.module` (resources declared with `.copy("Resources")` in Package.swift). `SamplePassages` exposes the bundled sample passages for the app's Sample button.
- `TextWatermarkAnalyzer`: `TextWatermarkProvider` protocol, `LocalStatisticalAnalyzer` (five-signal fusion, weights 0.40 uniformity + 0.20 repetition + 0.15 perplexity + 0.10 rare-word + 0.15 phrase, confidence ceiling 0.80, raw statistics as evidence), `AnthropicDetectionAPIProvider` (scaffolded, feature flagged, Keychain key via `KeyStoring`). Provider signals: detected, notDetected, insufficient, unavailable, inconclusive. `ProviderResult` carries an optional `caveatText` and `familyHints`; the combiner merges hints across providers (per family, strongest weight wins).
- `MediaFormat`: the list of file formats c2patool can verify today, with case-insensitive extension parsing and display names. Covers images (png, jpg, jpeg, svg, webp, avif, heic, heif, tif, tiff, dng), video (mp4, mov), audio (m4a, mp3, wav), and pdf (read-only).
- `FolderVerifier`: scans a folder recursively, verifies every supported file with `C2PAVerifier`, and returns a `BatchReport` (summary counts, per-file verdicts, failures). One broken file does not stop the scan; hidden files and unsupported extensions are skipped. `toolMissing` flags the case where c2patool cannot be launched.
- `TextWatermarkAnalyzer`: `TextWatermarkProvider` protocol, `LocalStatisticalAnalyzer` (burstiness + repetition heuristic, confidence ceiling 0.80, raw statistics as evidence), `AnthropicDetectionAPIProvider` (scaffolded, feature flagged, Keychain key via `KeyStoring`). Provider signals: detected, notDetected, insufficient, unavailable, inconclusive. `ProviderResult` carries an optional `caveatText` the combiner prefers.
- `VerdictCombiner`: merges provider results. A positive signal beats a negative one and the conflict is shown; short text caps confidence; inconclusive beats unavailable; insufficient beats unavailable; all-unavailable reports notAvailable. Every verdict carries evidence and a caveat.
- `HistoryStore`: `HistoryStoring` protocol, `JSONHistoryStore` actor, `HistoryRecorder` with hash-only defaults.
- `SHA256`: dependency-free, tested against known vectors.

The app (`App/`) is a macOS-only SwiftUI package: a NavigationSplitView main window with a sidebar (Check pane: paste text or drop a file, split into an input pane and a result pane; History pane: search, export JSON, delete, inline record details), a separate Settings scene opened with Cmd+, (providers, thresholds, retention, Keychain key), and a menu bar extra with clipboard check.

## Known tradeoffs and open items

- The official text detection API does not exist yet. The local statistical heuristic fills the gap and is honest about being a heuristic (moderate confidence ceiling, disclaimer caveats, raw statistics as evidence). When Anthropic ships the API, wire it into `AnthropicDetectionAPIProvider` behind the existing interface; it will override the heuristic for positive/negative signals from that provider.
- File verification used to depend entirely on c2patool being installed. As of 2026-08-17 PNG files are verified by the built-in `PNGC2PAReader` with no tool, and the built-in reader cannot validate signatures (no certificate-chain crypto), so a PNG checked without c2patool reports manifest-present but signature-unverifiable. All other formats still need c2patool; installing it remains the way to get full validation.
- History is JSON, not SQLite. Acceptable for the MVP; swap to GRDB or SwiftData when volume demands it.
- The app target is compiled on macOS by GitHub Actions CI on every push, and by the release workflow in release mode. The development sandbox is Linux, so CI is the real compile gate. The app is ad-hoc signed by the packaging script but not yet sandboxed or notarized; both need a developer certificate or the owner's Mac.
- The manifest parser uses heuristic mapping for signature validity and modification state. It is tested against the fixtures and documented; real-world c2patool output should be fed back into the fixture library as it appears.
- Modification is only reported when the signature verifies. A hash mismatch with an invalid or unverifiable signature proves nothing about the signer, so the verdict stays inconclusive instead of claiming the file changed after signing.

## Working notes for future sessions

- UI structure (2026-08-16): the main window is a NavigationSplitView with a sidebar (Check, History) and a detail pane. Settings is a separate Settings scene (Cmd+,), not a sidebar item. CheckView is a two-pane HSplitView (input left, result right); HistoryView is master-detail (list left, detail pane right). Check mode lives on AppState.checkMode; settings persistence lives in the SettingsPersistence ViewModifier attached to both scenes. Sidebar destinations are the AppSection enum. New UI components belong in App/Sources/OriginCheckApp/ as separate files, not inside a single view.
- Text heuristic (2026-08-17): `TextStatistics` (internal) computes burstiness (std/mean of sentence lengths, only sentences with >= 2 words count), repeated-bigram rate (bigrams keyed as lowercased words joined by a NUL), lexical diversity, token stats from the bundled dictionary, phrase matches, and the weighted AI-typical score (0.40 uniformity + 0.20 repetition + 0.15 perplexity + 0.10 rare-word + 0.15 phrase). Sentence splitting treats newlines and !? as breaks, and a period between digits is a decimal point, not a break. The analyzer needs at least 3 sentences and 40 words before it reports anything but insufficient. Tokenization (shared: `FrequencyDictionary.tokenize`) drops single-letter contraction remnants ("it's" -> it) and keeps bare a/i. UI verdict titles for text checks say "AI-typical pattern detected"/"No AI-typical pattern" while file verdicts keep C2PA wording; never blur the two in copy. Sample passages for the Check pane are bundled (`SamplePassages.bundled()`, three passages rotating on each tap); do not hardcode sample text in the view. NOTE: the phrase database intentionally contains words from the banned-words list (delve, seamless, robust, unlock, cutting-edge, game changer...): they are detection patterns in data, not product copy, and the voice rules do not apply to the resource files.
- Detection resources (2026-08-17): they live in `Sources/OriginCheckEngine/Resources/` and are declared with `.copy("Resources")` in the root Package.swift, so `Bundle.module.url(forResource:withExtension:subdirectory: "Resources")` finds them. The macOS packaging script copies the SwiftPM-emitted `*.bundle` into Contents/Resources (validate-app.sh gates on the three data files). If a new resource is added, it must be declared in Package.swift, embedded by package-app.sh (it copies all *.bundle), and validated by validate-app.sh.
- PNG reader (2026-08-17): `PNGC2PAReader` parses iTXt chunks (keyword NUL, compression flag, method, language tag, translated keyword, text), Base64-decodes, and walks JUMBF boxes (4-byte big-endian size, type; supports size 0 = to end and 1 = 8-byte extended) looking for JSON with "manifests" or "active_manifest". It ignores CRCs and compressed iTXt (c2pa stores uncompressed). Tests build synthetic PNGs that wrap the manifest in a real JUMBF superbox (jumd description + c2pa content box).
- Engine tests: `swift test` (works on Linux and macOS). The sandbox has Swift at /opt/swift/usr/bin; add it to PATH if it is not there.

Cut a release with `bash Scripts/release.sh v1.2.0` (see RELEASING.md). The DMG is the only install artifact; `checksums.txt` holds its SHA-256. Releases are ad-hoc signed and Sparkle-signed, not notarized.

- Settings include the c2patool path under `c2paToolPath` (defaults key `c2paToolPath`, default `c2patool`). `AppState.setC2PAToolPath` rebuilds the engine; `verifyFolder` always reads the current path from the engine. Never prefill that field with anything but the current stored value.
- `FolderVerifier` verifies in parallel chunks of 8 and throws `FolderVerifierError.directoryNotFound` / `.directoryUnreadable` instead of returning an empty report for a bad path. The batch card scrolls and caps per-file rows at 100.
- Batch history records: kind is always `.batchScan`, confidenceValue is 0 (counts, not a percentage), the input hash is a SHA-256 of the folder path, and `batchSummary` carries the counts. `HistoryView` renders counts instead of percent for these rows. Any new switch over `VerdictKind` (the app has two: `historyTitle` and `VerdictDisplay.text`) must handle `.batchScan`.
- Swift 6 gotcha in the app: `Task {}` does not inherit MainActor isolation, and observable app state must be `@MainActor` or every capture into a Task is a data-race error. Follow the existing patterns in CheckView and MenuBar when adding async UI work.
- The engine's `C2PAVerifier` runs c2patool in a detached task and drains stdout and stderr on background threads. Keep the tool run off the caller's executor (a blocking waitUntilExit on the main actor freezes the UI) and never read the pipes only after waitUntilExit (a manifest larger than the 64 KiB pipe buffer deadlocks the run).
- SwiftPM gotcha: the app package references the engine by path, and path dependencies are identified by the checkout folder name, not the manifest name. The repo folder is `idea`, so `App/Package.swift` uses `package: "idea"`. Renaming the checkout folder breaks the build; CI checks out into the repo name so it always matches.
- The platform's web checks do not apply to this repo anymore. The engine test suite is the verification gate.
